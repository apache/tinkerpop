# LICENSE and NOTICE rules

Decision rules condensed from the ASF guide (https://infra.apache.org/licensing-howto.html), the
ASF third-party license policy (https://www.apache.org/legal/resolved.html) and the Dependencies
section of `docs/src/dev/developer/for-committers.asciidoc`. When a rule here and a source
disagree, the source wins. Fix the rule here.

## The governing principle

LICENSE and NOTICE must exactly represent the contents of the distribution they reside in. Only
bundled bits matter. Transitive dependencies are no different from direct ones: they count only
if their bits are in the artifact. A binary distribution usually bundles more than the source
distribution, so its LICENSE and NOTICE differ from the source ones.

## License categories

| Category | Examples | Rule |
|---|---|---|
| A | Apache 2.0, MIT, BSD 2/3-clause, ISC, Boost 1.0 | May be bundled. |
| B | EPL 1.0/2.0, MPL, CDDL | May be bundled in binary form only. A dual-licensed component (logback's EPL/LGPL) is bundled under its Category B option. |
| X | GPL, AGPL, LGPL-only | May not be bundled. A dual license with an Apache option (javaparser's LGPL/Apache) is bundled under Apache. |

Look an unfamiliar license up in the resolved list rather than guessing. An unknown license is a
stop-and-ask, not an assumption.

## Licenses that waive their own requirements

The ASF guide has no exception for compiled code: "All redistributions must obey the licensing
requirements of the contents." What a binary owes is set by each component's own license, so read
its conditions for the form TinkerPop ships, usually bytecode in a jar.

- **A license that waives its notice for object code** puts nothing in LICENSE or NOTICE when
  TinkerPop ships that component only compiled. Boost 1.0 requires its notice "unless such copies
  or derivative works are solely in the form of machine-executable object code generated by a
  source language processor". Javac output qualifies, so a component known only as Boost-licensed
  and shipped only as bytecode needs nothing.
- **The waiver must cover everything shipped.** If the source distribution carries the component's
  source, or the binary carries its source or text resources, the waiver does not apply to those.
- **MIT, BSD and EPL** have no such waiver. BSD's second clause names binary redistribution
  explicitly. Their code needs an entry however it ships.
- **Record the reasoning** in the review report, and in `pitfalls.md` when the decision will come up
  again, so the next review does not re-raise it.

## LICENSE

- **Apache-licensed and uniform:** no entry needed. Listing it with its version is allowed for
  completeness, but TinkerPop's files do not, so do not start.
- **Any other approved license:** an entry in the existing pattern for that file, grouped under the
  license's heading (BSD-style, MIT, Other), naming the component and its version, with a pointer
  to a copy of its license under `licenses/`. The ASF guide asks for the version because licenses
  change between versions.
- **A sub-component under a different license inside an Apache dependency:** an entry of its own,
  naming where it is bundled (for example inside `jackson-core`) and where it was relocated to.
- **Source distribution:** an entry only for a third-party file committed to the repository. A
  dependency the build downloads is not in the source distribution.

## NOTICE

The developer docs' decision list, for each bundled component:

- No NOTICE in the bundled jar: no change.
- A NOTICE under a non-Apache license: no change. Its copyright lines stay in its license file.
- A NOTICE under the Apache license, not from an ASF project: include its copyright notification.
- A NOTICE from an ASF project: include only what differs from the ASF boilerplate. If it is
  boilerplate only, leave TinkerPop's NOTICE unchanged.

The ASF guide adds:

- Do not duplicate "This product includes software developed at The Apache Software Foundation".
  TinkerPop's own NOTICE already carries the ASF copyright line.
- Keep NOTICE brief. "Do not add anything to NOTICE which is not legally required."
- Copyright notices relocated out of source files must be preserved in NOTICE.

Boilerplate means the project name, the ASF copyright line and the "developed at the ASF" line.
Anything else, such as code grants, ported code or bundled third-party attributions, is content
to propagate.

## License files

- Each `licenses/<name>` file is the verbatim license text of one bundled component, copied from
  that component's jar or source release.
- Every file must be referenced by an entry, and every entry's file must be packed. The two lists
  must match exactly in every artifact.
- A shaded jar packs files into `META-INF/licenses/` through shade transformers. A zip copies its
  module's `src/main/static/licenses/` directory.
- New license files under `src/main/static/` need no ASF header. RAT excludes that path.
