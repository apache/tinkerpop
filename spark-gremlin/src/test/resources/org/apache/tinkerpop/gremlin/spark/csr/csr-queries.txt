# Queries for CsrMemoryRun over CsrBenchmarkDataGenerator output.
#
#   <id> | <small|large> | <systems or *> | <gremlin-lang text using g> [| ordered]
#
# small/large tags the size of the result the client receives. systems is a comma list from tinkergraph, csr-native,
# csr-facade, tinkergraph-computer, spark, or *. A trailing "ordered" field makes the result hash order-sensitive.
#
# Schema: vertex labels person, software, device, location; edge labels knows, created, uses, locatedIn. Vertex ids are
# longs 0..2^scale-1. Each vertex has stringLowCardinality (64 values), stringHighCardinality (unique) and mixedNumber,
# plus one of byteValue, shortValue, intValue, longValue, floatValue, doubleValue, bigIntegerValue, bigDecimalValue
# chosen by id modulo 8 (so intValue and longValue exist on one vertex in eight). Edges have a float weight.
# Sums and means avoid the floating point columns, which hold NaN and infinities and sum in an order that differs
# between systems.

# CSR-unfavorable queries. Three groups, each with its own graph:
#
#   fb-*    facade and fallback steps on the standard power-law graphs above (path, as/select, where, match, sack,
#           aggregate().by(), reducing children, mid-traversal V(), edge-property filters on in-edges). Roots are
#           chosen by label and property, never by limit() as the root, so that the results agree across systems. The
#           label and stringLowCardinality both come from the low bits of one hash (label index = category number
#           modulo 4), so the roots are person with category-4, never person with category-7 (that is a location).
#   rich-*  data the columnar snapshot handles badly, on a graph from "CsrBenchmarkDataGenerator rich":
#           vertex labels as above (exactly one each); edge labels as above. Vertex properties: name (unique), mixed
#           (int, long, double, String and boolean by id modulo 5; numbers in 0..999), tag (0-5 values, list
#           cardinality, tag-0..tag-15), location (1-3 values, city-0..city-49, meta-properties since and, on about
#           half, until), uuid, created (OffsetDateTime), elapsed (Duration), amount (BigDecimal), bignum (BigInteger),
#           blob (byte[]), listval, setval, mapval (List, Set and Map values with nested members), charval, shortval,
#           floatval, byteval, bio (several hundred characters, common prefix, unique suffix), sparse (int on about 2%),
#           nullable (null on a quarter, a string on a quarter), age (int 0..99), score (long 0..9999). Edge properties:
#           weight (double), mixedEdge (mixed types like mixed), since (OffsetDateTime).
#   sid-*   the same rich graph generated with --string-ids: vertex ids v<n>, edge ids e<n>. Written for a graph of at
#           least 2^16 vertices and 2^16 * edge factor edges, so that v0..v7 and e0..e7 exist.
# ---------------------------------------------------------------------------------------------------------------------

# ---------------------------------------------------------------------------------------------------------------------
# Graph algorithms (alg-*), on the standard power-law graphs. Each algorithm has a recipe written in plain Gremlin
# (docs/src/recipes), which runs on every system, and where TinkerPop has one a vertex-program step (pageRank(),
# connectedComponent(), shortestPath()), which only the graph computers can run: the -vp queries list
# tinkergraph-computer and spark, and the other systems report UNSUPPORTED. Both forms end in the same summary (a
# count, a min, a list of counts, the ids of a path), so that recipe and vertex program can be compared by result hash; the exception is
# alg-eigen-pagerank-vp, a different centrality whose top ten is compared with alg-eigen-walks by eye
# (extra.resultSample).
#
# Queries with a -p12, -p16 or -p18 suffix hard-code vertex ids of powerlaw-12 (scale 12), powerlaw-16 and
# powerlaw-18 (edge factor 16, default seed). The ids were chosen with CsrAlgorithmSources (tinkergraph-gremlin test
# sources; README "Graph algorithms" says how to rerun it), which also prints the expected values:
#   bsrc  degree-1 vertex (among the first 200 by id) whose three-hop both() reach is at least a quarter of the graph,
#         with the fewest messages sent by shortestPath() (it sends every shortest path it extends to every neighbor;
#         from the largest hub that is 0.2 billion paths within two hops on p16 and 1.6 billion on p18)
#   sink  largest in-degree, the target of the path queries (generator hubs are out-only or in-mostly)
#   src   at directed distance 3 from the sink, with the fewest out-walks of length 1-3 (unweighted pair)
#   wsrc  directed distance 2 or more, weighted distance to the sink reached within 3 hops, fewest out-walks of length
#         1-3 (weighted pair, so the 3-hop-bounded recipe and the unbounded shortestPath() agree)
#           bsrc  sink   src    wsrc   expected: sp (path vertices), wsp distance, bfs (counts at distance 1..3)
#   p12     1759  2166   3440   3440   4, 1.21521, [1,11,1105]; components 921, largest 3176; 1438 closed 3-walks
#   p16     1764  10358  57232  525    4, 1.01989, [1,59,18606]; components 19081, largest 46452
#   p18     1660  10358  97549  33986  4, 1.41942, [1,486,87293]; components 84051, largest 178067
# shortestPath() from bsrc sends about 0.2M (p12), 10M (p16) and 160M (p18) path messages within three hops.
# ---------------------------------------------------------------------------------------------------------------------

# alg: degree centrality (top ten by bothE() count, ties by id)
alg-degree-top10      | small | * | g.V().project('v', 'd').by(id).by(bothE().count()).order().by(select('d'), desc).by(select('v')).limit(10) | ordered

# alg: eigenvector centrality. The recipe counts out-walks of length 0-4 that end at each vertex; barrier() bulks the
# traversers at each step, without it the walks are enumerated one by one. pageRank() is the vertex-program reference.
alg-eigen-walks       | small | * | g.V().repeat(groupCount('m').by(id).out().barrier()).times(5).cap('m').order(local).by(values, desc).limit(local, 10)
alg-eigen-pagerank-vp | small | tinkergraph-computer,spark | g.V().pageRank().with(PageRank.propertyName, 'pageRank').with(PageRank.times, 20).order().by('pageRank', desc).by(id).limit(10).id() | ordered

# alg: connected components (weak), summarized as component count and largest component size. alg-cc-recipe runs a
# dedup() breadth-first search per vertex not yet seen, inside local(); the graph computers reject local() beyond the
# star graph. alg-cc-recipe-doc is the recipe of connected-components.asciidoc verbatim: since repeat() became a global
# parent (TINKERPOP-3200) it returns only the isolated vertices, so it is kept for reference and not in the matrix.
# alg-cc-vp reads the default component key, because gremlin-lang does not implement ConnectedComponent.propertyName.
alg-cc-recipe         | small | * | g.V().local(where(without('a')).union(identity(), repeat(both().dedup()).emit()).dedup().aggregate('a').count()).is(gt(0)).fold().project('components', 'largest').by(count(local)).by(max(local))
alg-cc-recipe-doc     | small | * | g.V().emit(or(cyclicPath(), not(both()))).repeat(where(without('a')).local(aggregate('a')).both()).until(cyclicPath()).group().by(path().unfold().limit(1)).by(path().unfold().dedup().fold()).select(values).unfold().count(local).fold().project('components', 'largest').by(count(local)).by(max(local))
alg-cc-vp             | small | tinkergraph-computer,spark | g.V().connectedComponent().groupCount().by('gremlin.connectedComponentVertexProgram.component').select(values).project('components', 'largest').by(count(local)).by(max(local))

alg-sp-recipe-p16     | small | * | g.V(57232L).repeat(out().simplePath()).until(or(hasId(10358L), loops().is(3))).hasId(10358L).path().count(local).min()
alg-sp-vp-p16         | small | tinkergraph-computer,spark | g.V(57232L).shortestPath().with(ShortestPath.edges, Direction.OUT).with(ShortestPath.target, hasId(10358L)).with(ShortestPath.maxDistance, 3).count(local).min()

alg-sp-vp-p18         | small | tinkergraph-computer,spark | g.V(97549L).shortestPath().with(ShortestPath.edges, Direction.OUT).with(ShortestPath.target, hasId(10358L)).with(ShortestPath.maxDistance, 3).count(local).min()

alg-wsp-vp-p16        | small | tinkergraph-computer,spark | g.V(525L).shortestPath().with(ShortestPath.edges, Direction.OUT).with(ShortestPath.distance, 'weight').with(ShortestPath.target, hasId(10358L)).with(ShortestPath.includeEdges, true).limit(1).map(unfold().id().fold())

alg-wsp-vp-p18        | small | tinkergraph-computer,spark | g.V(33986L).shortestPath().with(ShortestPath.edges, Direction.OUT).with(ShortestPath.distance, 'weight').with(ShortestPath.target, hasId(10358L)).with(ShortestPath.includeEdges, true).limit(1).map(unfold().id().fold())
